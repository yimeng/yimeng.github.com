看了一堆数值，却答不上一个简单的问题

HomePulse 攒了很多数据之后，我发现一个尴尬的事实：我盯着一堆仪表盘，却回答不了一个最普通的问题——“刚才家里到底发生了什么？”

我能看到某个传感器的实时数值：灯是开是关、温度是多少、功率是多少瓦。但把这些数值连起来，我还是不知道：是谁在洗澡？洗衣机洗到哪一步了？老人夜里起夜了几次？

这就是监控和理解的区别：

监控：这个传感器现在是什么值？
理解：家里刚才发生了什么活动？

监控是"看数值"，理解是"懂活动"。我一直在做前者，却误以为自己在做后者。

为什么单靠一个数据源，永远答不对

这条链路里，每一步产出的东西性质都不同：

flowchart LR
    e["设备与传感器"] --> c["采集
直采 / HA"]
    c --> s[("时序存储
观测事实")]
    s --> y["语义层
设备 / 事件 / 场景"]
    y --> i["洞察
归因 / 异常 / 建议"]

只有功率数据：我知道"有设备在用电"，但不知道是哪个——吹风机和热风枪的低档位功率可以几乎一样，功率形态不是设备的唯一指纹。

只有水流量数据：我知道"有人在用水"，但不知道是洗澡、洗衣还是冲马桶——洗澡和洗衣都是持续用水，流量形态可能很相似。

只有状态数据：我知道"浴霸开了"，但不知道为什么开——可能是洗澡、取暖、换气，甚至只是开了个照明。

单源数据只能告诉你"有个现象"，不能告诉你"发生了什么活动"。 这就是局限。

把多个源拼起来，事情就不一样了

我开始尝试把不同的数据源交叉印证，效果立刻不一样。

洗澡识别：燃气在烧 + 水流量大 + 浴霸开着 + 湿度上升。这四个信号单独看都模棱两可，放在一起，“有人在洗澡"这个结论就非常可信。

洗衣机程序识别：程序状态 + 水位变化 + 功率周期波动。三者联合，我能精确知道洗衣机现在是在洗涤、漂洗还是脱水，不用任何人告诉我。

老人夜间安全：北卧的人体存在传感器从"有人"变"无人” + 门磁开合 + 时间是凌晨两点。拼起来就是"老人起夜、走出了房间"，值得关注。

跨源数据的价值，在于互相印证，而不是互相替代。

但跨源有一条红线：别乱推断

跨源印证很好用，但我给自己划了一条红线：不跨源推断。

什么意思？A 源的现象，不能拿来解释 B 源。我踩过的坑：

  • 看到"水压 0.33"，就推断"上游供水出问题"——结果那个 0.33 单位是 MPa，压力完全正常，我硬编了一个不存在的故障；
  • 看到"功率均值下降"，就推断"设备停机了"——结果均值把启动尖峰抹平了，结论是错的。

还有两条配套原则：

  • 不用均值抹尖峰：回到原始样本做事件分析，别被分钟均值骗了；
  • 标注优先于算法：用户说"刚才关的是浴霸排气扇"，算法就去验证、去提取数值证据，而不是自己"猜设备"。

数据实验室真正的目标

想通这些之后，我给 HomePulse 重新定位：

数据实验室的目标，不是"存数据"，是"理解家里发生了什么"。

不是"这个传感器现在是什么值"，而是"家里刚才发生了什么活动、谁在做什么、设备在干什么"。

具体地说：

  • 谁在洗澡？—— 水、气、浴霸联合判断；
  • 洗衣机到哪一步？—— 程序、水位、功率联合判断；
  • 老人夜里安全吗？—— 人体存在、门磁、时间联合判断；
  • 哪台电器最耗电？—— 回路功率 + 设备身份映射。

这件事教给我什么

  1. 监控和理解决不是一回事。 前者看数值，后者懂活动；数据实验室要的是后者。

  2. 单源永远有局限。 功率、水、状态，任何一个单独都识别不了"活动"。

  3. 跨源交叉验证，是理解活动的唯一可靠路径。 但别越界去乱推断。

  4. 数据价值不在"存了多少"，在"能理解多少活动"。 一仓库看不懂的数字，不如几条能说清"刚才发生了什么"的证据。

教训一句话：数据实验室的价值，不体现在仪表盘的数量，体现在能不能回答"家里刚才发生了什么"。
